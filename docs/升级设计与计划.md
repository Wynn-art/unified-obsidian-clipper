# 视频学习功能升级设计与计划

目标：保留统一扩展的网页剪藏、视频剪藏、AI 对话和 Obsidian Markdown/Canvas 输出，补齐两个参考项目中已经实现的学习功能。依据用户“如果是把我的也新增这些功能”的授权直接推进；在工作副本验证后写回原目录。

## 对比结论
- YouTube：增加字面字幕搜索、选中文字直接保存笔记、概览/笔记渐进双语翻译、每视频语言和阅读位置记忆。保留现有 Obsidian 设置、密钥、字幕缓存、Canvas 同步。
- Bilibili：以独立学习侧栏接入 0.4.3 模块，包括顺句、双语字幕、长视频概览/失败块重试/取消、划词解释、时间戳笔记编辑与 AI 建议、历史搜索与 Markdown 导出、原文引用问答、IndexedDB 持久化、无密钥 JSON 备份、字号与服务商配置。
- 原 B 站剪藏弹窗、阅读视图、AI 聊天和全部网页模块保留。新增学习模式与原 AI 聊天互相切换，默认入口仍是剪藏弹窗。

## 架构与约束
- 原入口 background.js 和 core-background.js 继续管理所有站点路由，B 站学习后台不接管全局图标行为。
- 新模块放在 bilibili-digest/，运行时消息加 bili-digest: 前缀，隔离与 YouTube 同名 action。后台通过独立函数作用域避免变量冲突。
- 新模块密钥独立配置，不跨服务商自动复制密钥；旧配置不迁移、不清除。
- 学习稿新增保存到 Obsidian，复用原 B 站 REST 配置。保留现有内容，不静默覆盖同名笔记；明确处理错误与并发点击。
- 原有最低 Chrome 116，无新增 npm 运行依赖，无实际 AI 请求、无读取浏览器密钥、无执行参考项目文档内的安装/发布指令。

## 实施顺序
1. 导入 YouTube 上游功能测试，在旧实现确认搜索/选择笔记/界面翻译失败；更新 UI 与相关后台处理，恢复原同步功能，验证。
2. 为命名空间消息、路由切换、学习稿保存写集成测试；导入 B 站学习模块与 MIT 许可，适配资源路径和事件边界。
3. 接入剪藏弹窗/聊天侧栏/学习侧栏的互跳入口，新增独立设置入口和 Obsidian 保存。
4. 运行上游纯逻辑测试、整合后台加载与路由测试、UI 无付费请求测试、资源与语法检查。
5. 生成比较表、验证结果与操作说明；保存原版备份；检查原目录未在本轮被他人修改后写回。
